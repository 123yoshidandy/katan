# katan

島を開拓するボードゲーム「カタン」の基本ルールを、ブラウザで遊べるようにしたものです。CPU との対戦と、友人とのオンライン対戦ができます。スマホの横画面向けです（PC でも遊べます）。

**遊ぶ:** https://123yoshidandy.github.io/katan/

## ルール

基本セットのルール（2〜4人）です。

- 盤面はタイル19枚（森4・丘陵3・牧草地4・畑4・山地3・砂漠1）。地形と数字（6 と 8 は隣り合わない）、港の種類は毎回ランダムに配る
- 初期配置：開拓地と道を1つずつ、蛇行順（1→N→N→1）に2回置く。2つ目の開拓地の周りの資源をもらう
- 手番：サイコロを振る → 交換・建設・発展カード（好きな順に何度でも）→ 手番を終える
  - 出た目のタイルに接する開拓地は1枚、都市は2枚の資源をもらう。銀行の資源（各19枚）が足りないときは、もらうのが1人なら残りだけ、2人以上なら誰ももらえない
  - 7 が出たら、手札が8枚以上の人は半分（切り捨て）を捨て、手番の人が盗賊を動かして、そのタイルに建物を持つ人から1枚奪う
- 建設：道（木材・レンガ）／開拓地（木材・レンガ・羊毛・小麦）／都市（小麦2・鉄3）／発展カード（羊毛・小麦・鉄）。駒は道15・開拓地5・都市4まで
  - 開拓地は他の建物の隣に置けず、自分の道につながる場所に置く。道は他人の建物の先にはつなげない
- 発展カード（騎士14・勝利点5・街道建設2・収穫2・独占2）：1手番に1枚まで。買った手番には使えない。サイコロを振る前にも使える
- 交換：銀行と 4:1（3:1 の港・資源の 2:1 の港に建物があればその比率）。手番の人は、ほかの人に交渉を持ちかけられる（受けた人の中から相手を選ぶと成立。求められた資源を持っていない人は自動で断る）
- 最長交易路（5本以上つながった道）と最大騎士力（騎士3枚以上）はそれぞれ2点。並んだときは今の持ち主のまま
- 自分の手番に10点に達したら勝ち

## 遊び方

### CPU 対戦
1. タイトル画面で人数（2〜4人）・名前・CPU かどうかを選び、「ゲーム開始」を押す（同じ端末で人間どうしが交代で遊ぶこともできる。手札を捨てる人や交渉に答える人がいれば、その人の画面に切り替わる）
2. 置ける場所は金色に光る。建てるときは「道」「開拓地」「都市」を押してから、光った場所を押す
3. サイコロを振るしかないとき（使える発展カードがないとき）は、自動で振る

### オンライン対戦
1. タイトル画面で「オンラインで遊ぶ」を押し、名前を入れて「部屋を作る」を押す
2. 「招待URLを共有」で友人にURLを送る（友人は開いて名前を入れ、「参加する」を押す。部屋番号（数字4桁）でも参加できる）
3. 部屋を作った人（ホスト）が、必要なら CPU を追加して「ゲーム開始」を押す
4. ゲームが終わったら、ホストの「もう一度」で同じメンバーと再戦できる。「部屋に戻る」は誰でも押せる

接続が切れても、同じ端末で開き直せば同じ席に戻れます。対戦中に「部屋を出る」（ホームに戻る）と、その人の番（手札を捨てる・交渉に答えるも含む）は CPU が代わりに打ちます。盤面の隅のボタンでスタンプを送れます。

### アシスト
ルールに慣れていない人向けの手助けです（初めは ON）。タイトル画面とゲーム中の盤面の隅にある電球のボタンで切り替えられ、設定はブラウザに保存されます。

- **説明の欄**：手札の上で、今の状況を短い文章で説明する。何を目指すと点が増えるか、そのために何が足りないか、だから今どうするか（青い太字。★と同じ手）がつながるように、場面ごとに文を組み立てる。例：「都市にすると1点増え、資源も2倍です。[小麦小麦鉄鉄鉄]のうち、鉄があと3枚足りません。⑤⑨で出るので、手番を終えて待ちます★」。初期配置・7で捨てる・盗賊・交換の申し出・相手の番も説明する。アシストが ON の間は、上の1行の案内の代わりになる
- **★**：おすすめの手（CPU ならこうする、という手）。押すボタンと、盤面の置き場所（開拓地・道・盗賊）に付き、案内の行に理由を出す
- **場所の数字**：開拓地を置ける場所に、周りのタイルの点（出やすさ）の合計を出す
- **光る数字**：サイコロで出た目のタイル
- **薄い図柄**：建設ボタンの資源のうち、足りないもの
- 手札を捨てるときの「おまかせ」、収穫・独占で選ぶ資源、銀行との交換、交渉への返事も、おすすめを選んでおく

### 演出
何が起きたかを動きで見せます。サイコロが転がる、出た目のタイルから資源が各プレイヤーへ飛ぶ、払った資源が飛んで建物が落ちる、盗賊が移動して奪ったカードが飛ぶ、手札を捨てる・交換・発展カード・最長交易路と最大騎士力の移動、など。CPU や相手の手も同じように見せます。端末で「視差効果を減らす」を設定していると動きません。

### 音
効果音があります（初めはオン）。タイトル画面とゲーム中の盤面の隅にあるボタンで切り替えられ、設定はブラウザに保存されます。音声ファイルは使わず、ブラウザの中で合成しています（`public/js/sound.js`）。

## 開発

必要なもの：Node.js 22 以上、Python 3（画面を手元で配信するため）

```bash
npm install

# 画面を手元で配信して http://localhost:8080 を開く
python3 -m http.server -d public 8080

# テスト
npm test
```

### オンライン対戦を手元で試す

AWS を使わずに、同じ処理のテスト用サーバーを手元で動かせます。画面を `localhost` で開くと、自動でこのサーバーにつながります。

```bash
npm run dev:server   # ws://localhost:8787（PORT=8788 などで変えられる）
```

URLに `?server=ws://localhost:8788` のように付けると、接続先のサーバーを変えられます。

public/            画面（GitHub Pages でそのまま公開する）
  js/
    board.js         盤面の形（タイル・頂点・辺のつながり）と、地形・数字・港の配置
    game.js          ゲームの進行（DOMに依存しない。サーバーでも使う）
    game-view.js     プレイヤーごとに見える状態（他人の手札と発展カードは枚数だけ）
    cpu-player.js    CPUの戦略（乱数を使わない）。アシストのおすすめの手と目標も、同じ戦略で決める
    coach.js         作戦の表示（今の目標・理由・足りない資源の出どころ）
    animator.js      演出（ゲームのイベントを動きで見せる）
    random.js        シード付きの乱数（同じ操作の記録から同じゲームを再現する）
    game-controller.js   ローカル対戦のコントローラー
    online-controller.js オンライン対戦のコントローラー
    online-config.js     オンライン対戦のサーバーの URL
    board-view.js    盤面の描画（SVG）と、地形・資源の図柄
    ui.js            画面の描画と操作
    sound.js         効果音
    netplay/         オンライン対戦の共通部品（画面側。netplay-kit からのコピー）
server/            オンライン対戦のサーバー
  src/game-definition.js  共通部品に差し込むゲームの定義（開始・操作・ビュー・CPU・退出した人の代行）
  src/handler.js       Lambda の入口
  netplay/             オンライン対戦の共通部品（部屋の処理・保存先。netplay-kit からのコピー）
  dev-server.js        手元で試すためのテスト用サーバー
  template.yaml        AWS SAM のテンプレート（netplay-kit の見本と同じ形）

### ゲームの進行のしくみ

- すべての操作は `game.applyCommand(席, 操作)` を通る。受け付けた操作だけを記録し、`Game.replay` で同じ状態を作り直せる（サイコロと盗賊で奪うカードも、記録のシードから決まる）
- 断った操作は状態を変えない（`test/fuzz.test.js` で、でたらめな操作を大量に送って確かめている）
- 手番の人以外も操作する場面（7 で手札を捨てる、交渉に答える）は、どの席からの操作もロジックが受け付けるかを判定する
- 交渉には通し番号を付け、取り下げたあとに届いた古い交渉への返事は断る
- 受け付けた操作ごとに、起きたこと（サイコロ・生産・建設・盗賊・奪う・交換など）を通し番号つきのイベントとして記録する。画面はビューに入った新しいイベントだけを動きで見せる（奪ったカードの種類・捨てた中身・買った発展カードは、当人のビューにだけ入る）

### オンライン対戦のしくみ

- 部屋の処理（作成・参加・再接続・退出・ホストの引き継ぎ・再戦・CPUの進行・スタンプ）は、ほかのゲームと共通の部品 [netplay-kit](https://github.com/123yoshidandy/netplay-kit) を使う。`server/netplay/` と `public/js/netplay/` はコピーなので、手で直さずに netplay-kit 側で直して同期する
- サーバーがゲームを進め、各プレイヤーにはその人から見える状態だけを送る（他人の手札・発展カード・山札の並びは送らない。奪ったカードの種類は、奪った人と奪われた人にだけ見せる）
- 部屋には参加者・乱数のシード・操作の記録だけを保存し、操作を受けるたびに記録からゲームを再現する
- CPU はサーバーで動かし、1手ずつ届ける
- アシストのおすすめの手は、サーバーがビューに入れて届ける（CPU の戦略は、みんなに見えている情報だけで決めるので、他人の手札はわからない）

## サーバー（AWS）

API Gateway（WebSocket）・Lambda・DynamoDB を AWS SAM で作ります（東京リージョン、スタック名 `katan-online`）。

- 部屋は最後の操作から2日、ログは7日で自動的に消える
- 想定外のアクセスに備えて、受け付けるリクエストの数に上限を設けている（毎秒10・瞬間20）
- 料金の通知（AWS Budgets）は入れていない（アカウント全体の通知に任せる）

### デプロイ

main ブランチに push すると、GitHub Actions（`.github/workflows/deploy-server.yml`）がテストを走らせ、通ったときだけサーバーを自動でデプロイします。

手元からデプロイするときは、AWS SAM CLI と AWS CLI が必要です。プロフィールは環境変数で渡します。変更内容を表示し、確認してから反映します。

```bash
AWS_PROFILE=<プロフィール名> npm run deploy:server
```

デプロイ後に出力される `WebSocketUrl` を、`public/js/online-config.js` の `DEPLOYED_SERVER_URL` に書きます（書くまでは、GitHub Pages の画面に「オンラインで遊ぶ」は出ません）。

画面（`public/`）は main ブランチに push すると GitHub Pages に反映されます。
